# 束线保护信号接入 · 双路径规划

录入有向光纤段（段标识、起点、终点、非负整数延迟），经真实 HTTP 接口求出
起点到终点 **两条边互不重复、总延迟最小** 的保护链路；无法形成双路时返回
最小割的源侧节点集合与全部外出割边作为瓶颈证据。

## 算法

将每段光纤建模为容量 1、费用为延迟的有向弧，求流量 2 的**最小费用流**
（连续最短路 SSP + Johnson 势函数 + Dijkstra），再分解为两条路径。

- 保证**全局最优**：不是"先求一条最短路再删边"的贪心。贪心在局部最短路
  占用共享光纤时会误判无解；最小费用流会在整体上重选路径组合。
- 节点允许重合，允许并行光纤（同端点多条不同标识的段各占 1 单位容量）。
- 最大流不足 2 时，在残余网络上从起点做可达搜索：可达集合即最小割源侧
  集合，由该集合指向外部的全部原始段即所有外出割边。

## 最优段审计

工程师在结果页可对**当前基准双路**发起最优段审计，逐段回答：
"这一段是否在**全部**最小总延迟的双路方案中不可替代？"

判定不逐段重新求解，而是基于**最优二单位流残量网络中的零费用交换环**：

- 先在最终残余网络上用 Johnson 可行势标出折算费用为 0 的弧（G0）；
- 已用段 `e=(u,v)` **可替换** ⇔ 其反向弧折算费用为 0 且 u、v 在 G0
  同一强连通分量（即反向弧落在零费用交换环上）。沿环推一单位流量，
  直接分解出两条**不含该段、总延迟与基准完全相同**的完整替代链路
  作为见证，并自检链路连续、边互不重复、总延迟一致；
- 否则该段为**必经段**：所有最优双路都必须使用它，`witness` 恒为
  `null`，绝不伪造见证；
- 基准未使用的段标为"未选用"。

零延迟段、并行段、多个等价最优方案由同一判据自然覆盖；同一拓扑重复
审计（含按段复算）的归类与见证完全一致。编辑拓扑或发起较新审计后，
旧结论立即清除，在途/过期响应不会覆盖新草稿。

## 一键验收（Compose verify）

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify verify
# 或： docker compose run --build verify
```

`verify` 服务会依次执行并以退出码报告结果（全过为 0）：

1. 构建检查（字节码编译）；
2. `pytest`：求解器（含 4000 个随机有向图对全枚举蛮力的对拍）、
   最优段审计（1500 个随机图对独立枚举口径的逐段对拍 + 替代见证复核）、
   输入校验、HTTP 接口；
3. API/HTTP 冒烟与业务验收（`verify/acceptance.py`，对真实运行中的服务发请求）：
   - 贪心反例必须返回全局最优总延迟 12，并用**独立枚举**复核；
     校验两条路径边互不重复、链路连续、各路径延迟与总延迟均可复算；
   - 共享瓶颈：源侧集合 + 全部外出割边，并用独立最大流确认双路不存在、
     移除割边后路径数为 0；
   - 最优段审计：必经段（零见证）/可替换段（等延迟替代双路见证，独立
     枚举对拍归类）、按段复算一致性、重复审计稳定性、非法输入定位；
   - 负延迟、重复段标识、不存在端点、不可达输入均返回 400 且错误定位到具体字段；
   - 并行光纤/零延迟、静态页面与过期请求防护的冒烟。

## 接口

`POST /api/protected-paths`

```json
{
  "source": "S", "target": "T",
  "segments": [
    {"id": "e1", "from": "S", "to": "A", "delay": 1}
  ]
}
```

- 成功：`{"status":"ok","totalDelay":12,"paths":[{"delay":6,"segments":[...]}, ...]}`
- 无法形成双路：`{"status":"insufficient","cut":{"sourceSet":[...],"edges":[...]}}`
- 输入错误（负延迟/重复标识/端点不存在）或不可达：HTTP 400，
  `errors` 中每项带 `loc`（如 `segments[2].delay`）定位字段。

`POST /api/segment-audit`（最优段审计；请求体同上，可加可选 `segmentId`）

- 成功：
  ```json
  {
    "status": "ok", "totalDelay": 2,
    "baseline": [{"delay": 0, "segments": [...]}, ...],
    "segments": [
      {"id": "x", "from": "A", "to": "B", "delay": 2,
       "usedInBaseline": true,
       "classification": "replaceable | mandatory | unused",
       "label": "可替换段",
       "witness": [{"delay": 0, "segments": [...]}, ...]}
    ]
  }
  ```
  可替换段 `witness` 为两条完整替代链路（不含该段、总延迟等于
  `totalDelay`）；必经段与未选用段 `witness` 为 `null`。
  带 `segmentId` 时只返回该段（按段复算），结论与整表审计完全一致；
  段标识不存在返回 400 并定位到 `segmentId`。

## 前端行为

- 所有结果只来自真实接口；展示每条链路段标识、逐段延迟、路径延迟与
  可复算的最小总延迟（页面同时显示加法复算式）。
- 提交即清除旧结论；请求带单调序号并使用 `AbortController`，
  过期响应不会覆盖新草稿。
- 双路求解成功后，结果页出现"发起最优段审计"按钮：审计表逐段列出
  必经/可替换/未选用归类；点击已用段可按段复算，页面并列展示基准方案
  与替代方案的延迟、边集（被审计段高亮），供复核员逐段核对双路约束。
- 编辑拓扑、重新提交或发起较新审计（含按段复算）后，旧结论立即清除：
  审计与复算各有独立单调序号与 `AbortController`，过期响应不会覆盖
  新草稿；同一审计内重复查看同一段优先使用缓存，归类与见证保持一致。
