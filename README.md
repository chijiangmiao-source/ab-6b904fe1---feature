# 束线保护信号接入 · 双路径规划

录入有向光纤段（段标识、起点、终点、非负整数延迟），经真实 HTTP 接口求出
起点到终点 **两条边互不重复、总延迟最小** 的保护链路；无法形成双路时返回
最小割的源侧节点集合与全部外出割边作为瓶颈证据。求解后可在结果页发起
**最优段审计**：逐段判定该光纤段是否在全部最小总延迟双路方案中不可替代。

## 算法

将每段光纤建模为容量 1、费用为延迟的有向弧，求流量 2 的**最小费用流**
（连续最短路 SSP + Johnson 势函数 + Dijkstra），再分解为两条路径。

- 保证**全局最优**：不是"先求一条最短路再删边"的贪心。贪心在局部最短路
  占用共享光纤时会误判无解；最小费用流会在整体上重选路径组合。
- 节点允许重合，允许并行光纤（同端点多条不同标识的段各占 1 单位容量）。
- 最大流不足 2 时，在残余网络上从起点做可达搜索：可达集合即最小割源侧
  集合，由该集合指向外部的全部原始段即所有外出割边。

## 最优段审计

设 f 为最优二单位流（基准方案），e=(u,v) 为基准已用段、延迟 d。任意最优
流 f′ 与 f 的差是残余网络中费用为 0 的环流，因此：

- **e 可替换 ⟺ 残余网络中存在经过 e 反向边 (v,u) 的零费用交换环**，
  即残余网络中 u→v 的最短路费用恰为 d（若小于 d 即负费用环，与 f 最优
  矛盾，不会出现）。判定只做一次最优流，随后在同一残余网络上用
  Johnson 势 + Dijkstra 逐段判别，**不逐段重新求解**。
- 可替换段：沿零费用环推一单位流，得到**不含该段、总延迟与基准完全相同**
  的两条完整替代链路（见证），返回前做完整自检，绝不伪造见证。
- 必经段（唯一/全部最优方案都使用该段）：明确标注，**不提供**替代见证。
- 零延迟段、并行段与多个等价最优方案由同一准则自然覆盖；最短路按
  (费用, 节点编号) 确定性选取，重复审计同一段的归类与见证保持一致。

## 一键验收（Compose verify）

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify verify
# 或： docker compose run --build verify
```

`verify` 服务会依次执行并以退出码报告结果（全过为 0）：

1. 构建检查（字节码编译）；
2. `pytest`：求解器（含 4000 个随机有向图对全枚举蛮力的对拍）、输入校验、
   HTTP 接口、最优段审计（含 600 个随机图对独立蛮力逐段归类对拍）；
3. API/HTTP 冒烟与业务验收（`verify/acceptance.py`，对真实运行中的服务发请求）：
   - 贪心反例必须返回全局最优总延迟 12，并用**独立枚举**复核；
     校验两条路径边互不重复、链路连续、各路径延迟与总延迟均可复算；
   - 共享瓶颈：源侧集合 + 全部外出割边，并用独立最大流确认双路不存在、
     移除割边后路径数为 0；
   - 负延迟、重复段标识、不存在端点、不可达输入均返回 400 且错误定位到具体字段；
   - 并行光纤/零延迟、静态页面与过期请求防护的冒烟；
   - 最优段审计：唯一最优下已用段判为必经段且不伪造见证；多等价最优下
     可替换段的替代见证独立复核（完整双路、边互不重复、不含被审段、
     总延迟与基准相同）；按段复算与重复审计结果一致。

## 接口

`POST /api/protected-paths`

```json
{
  "source": "S", "target": "T",
  "segments": [
    {"id": "e1", "from": "S", "to": "A", "delay": 1}
  ]
}
```

- 成功：`{"status":"ok","totalDelay":12,"paths":[{"delay":6,"segments":[...]}, ...]}`
- 无法形成双路：`{"status":"insufficient","cut":{"sourceSet":[...],"edges":[...]}}`
- 输入错误（负延迟/重复标识/端点不存在）或不可达：HTTP 400，
  `errors` 中每项带 `loc`（如 `segments[2].delay`）定位字段。

`POST /api/segment-audit`（请求体同上，可选 `"segmentId"` 指定单段复算）

```json
{
  "status": "ok",
  "totalDelay": 12,
  "paths": [ ... 基准双路，与规划接口一致 ... ],
  "audits": [
    {"segmentId": "e5", "classification": "mandatory", "witness": null},
    {"segmentId": "e2", "classification": "replaceable",
     "witness": {"totalDelay": 12, "paths": [ ... 不含 e2 的等费替代双路 ... ]}}
  ]
}
```

- `classification`：`mandatory`（必经段，出现在每一个最小总延迟方案中，
  不提供见证）、`replaceable`（可替换，附不含该段且总延迟相同的替代双路
  见证）、`unused`（基准方案未使用该段，仅单段查询时可能出现）。
- 流不足/不可达/非法输入的响应与规划接口一致；审计返回的基准方案与
  规划接口完全相同。

## 前端行为

- 所有结果只来自真实接口；展示每条链路段标识、逐段延迟、路径延迟与
  可复算的最小总延迟（页面同时显示加法复算式）。
- 求解成功后可"发起最优段审计"：逐段列出必经段/可替换归类；可替换段
  并列展示基准方案与替代方案的延迟、边集与双路约束复算，并支持按段复算
  （复算结果须与首次判定一致）。
- 提交即清除旧结论；编辑拓扑立即使旧结论（含审计结论）失效；
  请求带单调序号并使用 `AbortController`，过期响应不会覆盖新草稿。
